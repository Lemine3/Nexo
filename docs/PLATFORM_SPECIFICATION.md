## 1. أهداف النظام

- **توحيد إدارة التجارة الإلكترونية** في منصة واحدة تغطي المنتجات، الطلبات، المخزون، العملاء، والفواتير دون الحاجة لأنظمة منفصلة.
- **تمكين البيع عبر واتساب** كقناة بيع رئيسية موازية للمتجر الإلكتروني (Conversational Commerce)، عبر كتالوج المنتجات، الرسائل التفاعلية، وروابط "Click to WhatsApp".
- **دعم الهيكلية المؤسسية المعقدة**: شركات بها فروع ومتاجر متعددة، عاملة في أكثر من دولة وعملة ومنطقة زمنية، مع تسلسل صلاحيات هرمي من المالك حتى موظف التوصيل.
- **أتمتة العمليات التكرارية**: الردود التلقائية، استرجاع السلة المهجورة، التوصيات الذكية، تجديد المخزون، وإصدار الفواتير.
- **تعزيز اتخاذ القرار بالبيانات**: تحليلات لحظية، تقارير قابلة للتخصيص، ولوحات KPI لكل دور.
- **ضمان الأمان وقابلية التدقيق**: حماية بيانات العملاء والمدفوعات، وتتبع كل عملية عبر سجل تدقيق كامل.
- **قابلية التوسع الأفقي**: البنية التقنية يجب أن تتحمل نمو عدد المتاجر والمستخدمين والطلبات دون إعادة هندسة جذرية.
- **الجاهزية متعددة المنصات**: ويب متجاوب، PWA قابل للتثبيت، وأساس تقني (API-first) يسمح ببناء تطبيقات Android/iOS لاحقًا دون تعديل الخلفية (Backend).
- **تجربة عميل سلسة (Omnichannel)**: توحيد نقاط تواصل العميل (متجر، واتساب، بريد، SMS، إشعارات Push) في واجهة واحدة للموظف.

## 2. وصف كامل للمنصة

Nexo هي منصة SaaS للتجارة الإلكترونية متعددة المستأجرين (Multi-tenant) وقابلة كذلك للنشر كحل مستقل لعميل واحد (Single-tenant)، تخدم التجار الذين يديرون متجرًا إلكترونيًا واحدًا أو أكثر، بفروع مادية أو دون فروع، ويبيعون منتجات مادية و/أو رقمية.

تتكون المنصة من ثلاث طبقات رئيسية:

1. **واجهة المتجر (Storefront)**: متجر إلكتروني متجاوب (Responsive + PWA) يعرض المنتجات، يدير سلة الشراء، ويكمل الدفع، بدعم كامل لتعدد اللغات (بما فيها العربية RTL) والعملات.
2. **لوحات الإدارة (Back-office)**: مجموعة لوحات تحكم مخصصة لكل دور وظيفي (Owner, Super Admin, Admin, Manager, Support, Sales, Marketing, Finance, Warehouse, Delivery)، كل لوحة تعرض فقط الوحدات والبيانات المصرح بها لصاحب الدور.
3. **طبقة القنوات والتكاملات (Channels & Integrations)**: تكامل عميق مع WhatsApp Business Platform API، بوابات الدفع، شركات الشحن، بوابات الرسائل النصية والبريد، ومحرك بحث/توصيات ذكي.

يُبنى النظام على مبدأ **API-first**: كل وظيفة في لوحات الإدارة والمتجر تُنفَّذ عبر REST API (وGraphQL اختياريًا) موثقة بالكامل، بحيث يمكن لاحقًا بناء تطبيقات جوال أصلية (Android/iOS) أو تكاملات خارجية دون أي تعديل في منطق الخلفية.

## 3. تحليل أنواع المستخدمين

### 3.1 مستخدمو النظام الداخليون (Staff / Back-office Users)

| الدور | الوصف | نطاق الوصول النموذجي |
|---|---|---|
| **Owner (المالك)** | صاحب الحساب الرئيسي على مستوى المؤسسة/المستأجر (Tenant). صلاحيات مطلقة غير قابلة للتقييد. | كل المتاجر، كل الفروع، الإعدادات المالية والفوترة الخاصة بالاشتراك في المنصة نفسها. |
| **Super Admin** | يدير المنصة بالكامل نيابة عن المالك، بما في ذلك إدارة باقي المدراء والصلاحيات. | جميع الوحدات، لا يمكنه حذف المالك أو تغيير خطة الاشتراك (اختياريًا). |
| **Admin** | إدارة تشغيلية شاملة لمتجر أو مجموعة فروع محددة. | الوحدات التشغيلية كافة ضمن النطاق المخصص له، دون إعدادات الفوترة العليا. |
| **Manager** | مدير فرع/قسم، يشرف على فرق العمل (مبيعات، دعم، مخزون) ضمن فرع واحد. | تقارير الفرع، إدارة الموظفين التابعين له، الموافقة على استثناءات محدودة (خصومات، مرتجعات). |
| **Support (الدعم الفني/دعم العملاء)** | يرد على استفسارات العملاء عبر القنوات المختلفة. | مركز المحادثات، ملفات العملاء، الطلبات (عرض فقط أو تعديل محدود)، التذاكر. |
| **Sales (المبيعات)** | يتابع العملاء المحتملين، يدير عروض الأسعار والطلبات اليدوية. | CRM، الطلبات، العملاء، الكوبونات (اقتراح لا اعتماد). |
| **Marketing (التسويق)** | يدير الحملات، الكوبونات، العروض، وقوالب واتساب/البريد. | الحملات، العروض، الكوبونات، تحليلات التسويق، قوالب الرسائل. |
| **Finance (المالية)** | يدير الفواتير، الضرائب، التسويات، والتقارير المالية. | الفواتير، المدفوعات، الضرائب، التقارير المالية، المحافظ. |
| **Warehouse (المخزون)** | يدير حركة المخزون بين الفروع والمستودعات. | المخزون، تحويلات المستودعات، الجرد، أوامر الشراء. |
| **Delivery (التوصيل)** | مندوب توصيل أو منسق شحنات. | الطلبات المخصصة له فقط (حالة، عنوان، تأكيد التسليم)، لا يرى بيانات مالية أو عملاء آخرين. |

### 3.2 مستخدمو المتجر (Customer-facing Users)

- **زائر غير مسجل (Guest)**: تصفح، بحث، إضافة للسلة، شراء كضيف (إن سُمح بذلك).
- **عميل مسجل (Customer)**: حساب دائم، سجل طلبات، محفظة ونقاط ولاء، عناوين محفوظة، قوائم أمنيات.
- **عميل جملة (B2B / Wholesale)** *(اختياري حسب الباقة)*: أسعار خاصة، حدود ائتمان، موافقات طلبات.
- **الشريك/التابع (Affiliate)** *(اختياري)*: روابط إحالة وعمولات.

### 3.3 مستخدمو API/تكاملات

- **تطبيقات الطرف الثالث** عبر مفاتيح API/OAuth Apps (مثل أنظمة محاسبة خارجية أو ERP).
- **حسابات خدمة (Service Accounts)** للتكاملات الآلية (Webhooks الواردة من واتساب، بوابات الدفع، شركات الشحن).

## 4. لوحات التحكم حسب الدور

كل لوحة تُبنى كواجهة مستقلة منطقيًا (Route-guarded) تعرض فقط القوائم والبيانات التي تسمح بها صلاحيات المستخدم (انظر قسم RBAC). المكونات المشتركة (تنقل، إشعارات، بحث) واحدة، لكن محتوى الشريط الجانبي والـ widgets يتغير حسب الدور.

### 4.1 لوحة Owner (صلاحيات مطلقة)
- نظرة عامة تنفيذية شاملة (كل الفروع/المتاجر/الدول) في شاشة واحدة.
- إدارة خطة الاشتراك والفوترة الخاصة بالمنصة (Billing of the SaaS itself)، إضافة/حذف متاجر بالكامل.
- إدارة كل الأدوار بما فيها إنشاء/حذف حسابات Super Admin.
- الوصول الكامل لسجلات التدقيق (Audit Logs) غير القابلة للتعديل من أي دور آخر.
- إعدادات أمان المؤسسة (سياسات كلمات المرور، 2FA الإلزامي، IP Whitelisting).
- تصدير كامل للبيانات (Data Export/Portability) وإدارة النسخ الاحتياطية.

### 4.2 لوحة Super Admin
- كل صلاحيات Admin + إدارة الأدوار والصلاحيات المخصصة (Custom Roles Builder).
- إدارة التكاملات على مستوى المؤسسة (WhatsApp Business API، بوابات الدفع، شركات الشحن).
- إدارة إعدادات النظام العامة (اللغات، العملات، الضرائب الافتراضية).
- مراقبة الأداء والتنبيهات على مستوى النظام.

### 4.3 لوحة Admin
- إدارة شاملة لمتجر/مجموعة فروع: منتجات، طلبات، عملاء، مخزون، موظفين.
- إعداد سياسات الشحن والدفع الخاصة بالمتجر.
- إدارة الكوبونات والعروض والحملات التسويقية.
- تقارير تشغيلية ومالية على مستوى المتجر.

### 4.4 لوحة Manager
- لوحة أداء الفرع/القسم (مبيعات اليوم، طلبات معلقة، مخزون منخفض).
- إدارة جداول ومهام الموظفين التابعين.
- الموافقة/الرفض على طلبات استثناء (خصم يدوي، إرجاع خارج السياسة).

### 4.5 لوحة Support
- صندوق وارد موحد (Omnichannel Inbox): واتساب، بريد، شات الموقع.
- عرض 360° لملف العميل: الطلبات، المحادثات السابقة، الشكاوى.
- نظام تذاكر (Tickets) مع SLA وتصعيد (Escalation).
- قاعدة معرفة (FAQ) للردود السريعة.

### 4.6 لوحة Sales
- خط أنابيب المبيعات (Pipeline) بأسلوب Kanban للعملاء المحتملين.
- إنشاء طلبات/عروض أسعار يدوية نيابة عن العميل.
- متابعة الأهداف الشهرية والعمولات.

### 4.7 لوحة Marketing
- إدارة الحملات (بريد، SMS، واتساب، Push) مع جدولة وشرائح جمهور (Segments).
- بناء الكوبونات والعروض وقواعد التطبيق (منتج/فئة/حد أدنى للسلة).
- تحليلات الحملات (معدل الفتح، النقر، التحويل، ROI).
- إدارة قوالب رسائل واتساب (Templates) وموافقات Meta.

### 4.8 لوحة Finance
- إدارة الفواتير (إصدار، إلغاء، إشعارات دائن/مدين).
- تسويات المدفوعات وربطها بالطلبات وبوابات الدفع.
- إدارة الضرائب (VAT/GST) حسب الدولة والفئة.
- تقارير الأرباح والخسائر، التدفق النقدي، والمستحقات.
- إدارة المحافظ الإلكترونية للعملاء ونقاط الولاء من الناحية المحاسبية.

### 4.9 لوحة Warehouse
- إدارة المخزون متعدد المستودعات/الفروع مع حدود إعادة الطلب (Reorder Points).
- أوامر الشراء ومتابعة الموردين.
- الجرد الدوري والتسويات (Stock Adjustments) مع سبب موثق لكل تعديل.
- تتبع تحويلات المخزون بين الفروع.

### 4.10 لوحة Delivery
- قائمة الشحنات المخصصة للمندوب فقط، مرتبة حسب المسار/الأولوية.
- تحديث حالة الطلب (تم الاستلام، في الطريق، تم التسليم، تعذر التسليم) مع صورة/توقيع إثبات.
- خرائط وتوجيه (Navigation Integration).
- تسوية المبالغ المحصلة نقدًا عند الاستلام (Cash on Delivery Reconciliation).

## 5. نظام الصلاحيات RBAC

### 5.1 المبادئ
- **Role-Based Access Control** هرمي مع دعم **صلاحيات مخصصة (Custom Permissions)** فوق الأدوار الجاهزة.
- كل صلاحية تُعرَّف كثلاثية: **`(Resource, Action, Scope)`** — مثال: `(orders, refund, branch:12)`.
- الإجراءات القياسية لكل مورد: `view`, `create`, `update`, `delete`, `export`, `approve`, و إجراءات خاصة بالمورد (مثل `refund`, `void_invoice`).
- **النطاق (Scope)** متعدد المستويات: `global` → `country` → `store` → `branch` → `self` (بيانات المستخدم نفسه فقط، كحالة مندوب التوصيل).

### 5.2 آلية العمل
- كل مستخدم مرتبط بدور أساسي واحد أو أكثر (Multi-role) + مجموعة استثناءات صلاحيات فردية (Overrides: Grant/Deny).
- التحقق من الصلاحية يتم في طبقة الـ Middleware/Guard في الـ API قبل الوصول لأي Controller، وأيضًا في الواجهة لإخفاء عناصر الواجهة غير المصرح بها (Defense in depth: لا يُعتمد على إخفاء الواجهة فقط).
- **مصفوفة صلاحيات افتراضية** لكل دور من الأدوار العشرة المذكورة في القسم 4، قابلة للاستنساخ والتعديل عبر "Custom Roles Builder" في لوحة Super Admin.
- دعم **Attribute-Based rules** إضافية عند الحاجة (مثال: مسؤول المبيعات يمكنه منح خصم بحد أقصى 10% فقط).
- كل تغيير في الصلاحيات يُسجَّل في Audit Log (من غيّر ماذا، ولمن، ومتى).

### 5.3 مثال مصفوفة (مختصر)

| المورد | Owner | Super Admin | Admin | Manager | Sales | Support | Finance | Warehouse | Delivery |
|---|---|---|---|---|---|---|---|---|---|
| المنتجات | CRUD | CRUD | CRUD | تعديل محدود | عرض | عرض | عرض | عرض مخزون | - |
| الطلبات | CRUD | CRUD | CRUD | اعتماد استثناءات | إنشاء/عرض | عرض/تعليق | عرض مالي | عرض شحن | تحديث حالة (المخصص له) |
| الفواتير | CRUD | CRUD | عرض/إصدار | عرض | - | - | CRUD | - | - |
| الموظفون | CRUD | CRUD | إدارة فرعه | إدارة فريقه | - | - | - | - | - |
| الإعدادات العامة | CRUD | CRUD | إعدادات متجره | - | - | - | إعدادات مالية | إعدادات مخزون | - |

## 6. الوحدات الإدارية الأساسية

- **إدارة الموظفين**: ملفات الموظفين، الأدوار، الفروع المخصصة، جداول الدوام، تقييم الأداء، سجل الحضور (اختياري)، إنهاء/تعليق الحساب.
- **إدارة العملاء**: ملف موحد 360° (بيانات، عناوين متعددة، طرق دفع محفوظة، سجل طلبات، سجل تواصل عبر كل القنوات، ملاحظات داخلية، شرائح/Tags، مستوى الولاء).
- **إدارة المنتجات**: منتجات بسيطة/متغيرات (Variants: مقاس/لون)، منتجات رقمية، حزم (Bundles)، وحدات قياس متعددة، صور/فيديو، SEO metadata، حالة النشر، تسعير متعدد العملات.
- **إدارة الفئات**: شجرة فئات هرمية غير محدودة العمق، فئات مخصصة لكل متجر/دولة، ربط فلاتر البحث بالفئة.
- **إدارة العلامات التجارية**: صفحات براند مستقلة، شعار، وصف، ربط بالمنتجات والفلاتر.
- **إدارة الطلبات**: دورة حياة كاملة (معلق → مؤكد → قيد التجهيز → تم الشحن → تم التسليم → مكتمل/ملغى/مرتجع)، طلبات جزئية الشحن، دمج/تقسيم طلبات، سجل تغييرات الحالة.
- **إدارة الفواتير**: إصدار تلقائي عند تأكيد الطلب، فواتير ضريبية متوافقة مع كل دولة، إشعارات دائن/مدين، تصدير PDF، أرشفة.
- **إدارة المخزون**: تتبع الكمية لكل متغير ولكل فرع/مستودع، حجز المخزون عند إنشاء الطلب، تنبيهات نفاد المخزون، جرد دوري، تكلفة المخزون (FIFO/Weighted Average اختياري).
- **إدارة المرتجعات (Returns/RMA)**: طلب إرجاع من العميل أو الموظف، أسباب موثقة، فحص الحالة، استرداد للمحفظة/طريقة الدفع الأصلية، إعادة المخزون.
- **إدارة الكوبونات**: أكواد خصم (نسبة/قيمة ثابتة/شحن مجاني)، شروط الاستخدام (حد أدنى، فئة، عدد مرات، تاريخ صلاحية)، كوبونات حصرية لعميل/شريحة.
- **إدارة العروض**: عروض توقيتية (Flash Sales)، عروض كمية (اشترِ 2 واحصل على 1)، عروض حزم، جدولة تلقائية للبدء/الانتهاء.

## 7. التجارة والمالية

- **نظام الولاء**: نقاط تُكتسب عند الشراء/التقييم/الإحالة، مستويات عضوية (Bronze/Silver/Gold) بمزايا متدرجة، قواعد انتهاء صلاحية النقاط.
- **المحافظ والنقاط**: محفظة إلكترونية لكل عميل (رصيد نقدي قابل للاستخدام كطريقة دفع)، سجل حركات كامل (إيداع/سحب/استرداد)، تحويل النقاط إلى رصيد محفظة حسب معدل تحويل قابل للتهيئة.
- **إدارة الضرائب**: قواعد ضريبية لكل دولة/منطقة/فئة منتج، ضرائب مركّبة، إعفاءات، عرض السعر شامل/غير شامل الضريبة حسب الدولة.

## 8. الشحن والدفع والعملات واللغات

- **إدارة الشحن**: مناطق شحن، أسعار حسب الوزن/الحجم/المسافة، شحن مجاني بشرط، طرق استلام من الفرع (Click & Collect).
- **إدارة شركات الشحن**: تكامل عبر API مع شركات شحن متعددة (توليد بوليصة، تتبع، حساب تكلفة لحظي)، إمكانية إضافة شركة شحن يدوية.
- **إدارة وسائل الدفع**: تكامل مع بوابات دفع متعددة (بطاقات، محافظ رقمية محلية وعالمية، الدفع عند الاستلام، تحويل بنكي)، دعم Tokenization لعدم تخزين بيانات البطاقة مباشرة (توافق PCI-DSS).
- **إدارة العملات**: تعدد العملات مع تحديث أسعار الصرف (يدوي/تلقائي عبر مزود خارجي)، عرض السعر بعملة المستخدم مع تخزين المحاسبة بعملة أساسية موحدة.
- **إدارة اللغات**: تعدد اللغات للواجهة والمحتوى (بما فيها دعم RTL الكامل للعربية)، ترجمة المنتجات/الفئات لكل لغة، كشف تلقائي للغة المتصفح.

## 9. تكامل WhatsApp Business Platform

تكامل كامل مع **WhatsApp Business Platform (Cloud API)** من Meta، يشمل:

- **Webhooks**: استقبال ومعالجة أحداث الرسائل الواردة، تحديثات حالة التسليم (sent/delivered/read/failed)، مع التحقق من التوقيع (`X-Hub-Signature-256`) ومعالجة غير متزامنة عبر طابور رسائل (Queue) لضمان الاستجابة السريعة لواجهة Meta.
- **إدارة Templates**: إنشاء/تعديل/إرسال قوالب رسائل معتمدة من Meta (Marketing/Utility/Authentication)، متابعة حالة الموافقة، دعم المتغيرات الديناميكية والوسائط (صور/مستندات).
- **Interactive Messages**: أزرار الرد السريع (Quick Reply)، أزرار CTA (فتح رابط/اتصال).
- **List Messages**: قوائم اختيار متعددة الأقسام (مثال: عرض فئات المنتجات أو خيارات الدعم الفني).
- **Product Catalog**: ربط كتالوج المنتجات (Meta Commerce Catalog) لعرض وبيع المنتجات مباشرة داخل واتساب (رسائل كتالوج/منتج مفرد/سلة واتساب Native).
- **Click to WhatsApp (CTWA)**: دعم روابط/إعلانات "تواصل عبر واتساب" مع تتبع مصدر المحادثة (Ad/Campaign attribution) وربطها بـ CRM.
- **الردود التلقائية**: قواعد ردود مبنية على كلمات مفتاحية/نية، رسائل ترحيب وخارج أوقات العمل، تدفقات محادثة (Flows) بسيطة بدون كود (Flow Builder).
- **البوت الذكي المدعوم بالذكاء الاصطناعي**: فهم اللغة الطبيعية (NLU) للاستفسارات الشائعة (حالة الطلب، الأسعار، التوفر)، تصعيد سلس لموظف بشري عند الحاجة مع تسليم كامل السياق (Conversation Handoff)، دعم متعدد اللغات.

## 10. CRM ومركز المحادثات الموحد (Omnichannel)

- **CRM متكامل**: إدارة العملاء المحتملين (Leads) والعملاء الحاليين، خط أنابيب مبيعات، تذكيرات متابعة، ربط كل تفاعل (طلب، محادثة، تذكرة) بالملف الموحد للعميل.
- **مركز محادثات Omnichannel**: صندوق وارد واحد يجمع واتساب، بريد إلكتروني، شات الموقع، وSMS، مع توزيع تلقائي للمحادثات على الموظفين (Round-robin/حسب الحمل)، وسوم (Tags)، وحالة (مفتوحة/معلقة/مغلقة)، وSLA لكل محادثة.

## 11. الإشعارات

- **إدارة الإشعارات**: مركز إعدادات موحد لتفعيل/تعطيل كل نوع إشعار لكل حدث (طلب جديد، تغيير حالة، عرض، تذكير سلة مهجورة) ولكل قناة.
- **البريد الإلكتروني**: قوالب HTML قابلة للتخصيص، تكامل مع مزودي SMTP/Transactional Email، تتبع معدلات الفتح/النقر.
- **الرسائل النصية (SMS)**: تكامل مع مزودي SMS محليين/عالميين، رموز تحقق (OTP)، تنبيهات حرجة.
- **إشعارات Push**: للمتجر (Web Push) ولاحقًا للتطبيقات الجوالة، مجدولة أو فورية، مستهدفة حسب شريحة.

## 12. الذكاء الاصطناعي والتوصيات

- **نظام البحث الذكي**: بحث نصي كامل (Full-text search) مع تصحيح إملائي، بحث بالمرادفات، فلاتر ديناميكية، وترتيب النتائج حسب الصلة والشعبية.
- **التوصيات الذكية**: "منتجات مشابهة"، "غالبًا يُشترى معًا"، توصيات مخصصة بناءً على سجل التصفح والشراء (Collaborative/Content-based Filtering).
- **استرجاع السلة المهجورة**: كشف تلقائي للسلال المتروكة، تذكير عبر بريد/SMS/واتساب بعد فترات زمنية متدرجة، حوافز اختيارية (كوبون تلقائي).
- **Upsell وCross-sell**: اقتراحات ترقية أثناء التصفح/السلة/بعد الشراء، وقواعد عرض قابلة للتخصيص من لوحة Marketing.

## 13. التحليلات والتقارير

- **تحليلات وتقارير متقدمة**: مبيعات، عملاء، منتجات، تسويق، مخزون — قابلة للفلترة والتصدير (CSV/Excel/PDF) وجدولة إرسال دوري بالبريد.
- **Dashboard لحظية**: مؤشرات أداء حية (طلبات اليوم، الإيرادات، الزوار الحاليون) عبر WebSocket لتحديث فوري دون تحديث الصفحة.
- **سجل العمليات (Audit Logs)**: تسجيل غير قابل للتعديل لكل عملية حساسة (من، ماذا، متى، من أين/IP)، بحث وفلترة، أرشفة طويلة المدى.

## 14. الأمان

- **النسخ الاحتياطية**: نسخ تلقائية يومية/أسبوعية لقاعدة البيانات والملفات، تخزين في موقع منفصل جغرافيًا، اختبار استعادة دوري، سياسة احتفاظ (Retention Policy).
- **نظام مراقبة الأداء**: مراقبة زمن الاستجابة، استخدام الموارد (CPU/RAM/DB)، معدل الأخطاء، مع تتبع تتبّعي (Tracing) للطلبات البطيئة.
- **نظام التنبيهات**: تنبيهات فورية (بريد/SMS/Slack/Webhook) عند تجاوز حدود معينة (فشل دفعات، توقف خدمة، مخزون حرج، محاولات دخول مشبوهة).
- **المصادقة والتفويض**: **OAuth 2.0** للتكاملات الخارجية، **JWT** (Access + Refresh Tokens قصيرة العمر مع تدوير) لجلسات المستخدمين، **2FA** (TOTP/SMS) إلزامي للأدوار الإدارية العليا.
- **Rate Limiting**: حدود طلبات لكل مستخدم/IP/مفتاح API، حماية خاصة لنقاط تسجيل الدخول وWebhooks.
- **التشفير**: تشفير البيانات الحساسة أثناء التخزين (At-rest, AES-256) وأثناء النقل (TLS 1.2+ إلزامي)، تجزئة كلمات المرور (bcrypt/argon2).
- **WAF (Web Application Firewall)**: حماية من هجمات الحقن (SQLi/XSS)، وDDoS الأساسي، وقواعد مخصصة لنقاط API الحساسة.
- **مراقبة أمنية**: كشف تسجيل الدخول الشاذ، قفل الحساب بعد محاولات فاشلة متكررة، تنبيه فوري للمالك عند تغييرات صلاحيات حرجة.

## 15. البنية التقنية والمعمارية

- **REST API**: واجهة برمجية شاملة (Versioned, مثل `/api/v1/...`) لكل وظيفة في النظام، موثقة عبر OpenAPI/Swagger.
- **GraphQL** *(اختياري)*: طبقة استعلام مرنة للاستهلاك من واجهات معقدة (تطبيقات جوال/لوحات مخصصة) عند الحاجة لتقليل عدد الطلبات.
- **WebSocket**: لتحديثات لحظية (لوحة المعلومات، مركز المحادثات، تحديث حالة الطلب).
- **Queue System**: طابور مهام (مثل RabbitMQ/SQS/Redis Streams) لمعالجة غير متزامنة (إرسال إشعارات، معالجة Webhooks، توليد فواتير/تقارير ثقيلة).
- **Redis Cache**: تخزين مؤقت للبيانات كثيفة القراءة (كتالوج المنتجات، إعدادات)، وجلسات، وRate Limiting counters.
- **CDN**: توزيع الأصول الثابتة (صور، JS، CSS) عالميًا لتقليل زمن التحميل.
- **تخزين الملفات**: تخزين كائنات (Object Storage متوافق مع S3) للصور والمستندات والنسخ الاحتياطية، مع روابط موقعة (Signed URLs) للوصول الآمن.
- **بنية Microservices** *(عند الحاجة/النمو)*: فصل الخدمات ذات الحمل العالي أو دورة النشر المستقلة (مثل: خدمة الإشعارات، خدمة الدفع، خدمة WhatsApp) عن الـ Monolith الأساسي، عبر بوابة API (API Gateway) وBroker رسائل مشترك؛ يُوصى بالبدء بـ **Modular Monolith** والانتقال التدريجي.
- **قاعدة بيانات قابلة للتوسع**: قاعدة علائقية أساسية (PostgreSQL/MySQL) مع دعم Read Replicas وTable Partitioning للجداول الكبيرة (الطلبات، سجل التدقيق)، مع إمكانية استخدام مخزن NoSQL تكميلي (مثل MongoDB/Elasticsearch) للبحث والتحليلات.
- **تصميم متجاوب**: واجهات Mobile-first تعمل على كل أحجام الشاشات.
- **دعم PWA**: تثبيت على الشاشة الرئيسية، عمل جزئي دون اتصال (Offline caching للصفحات الأساسية)، إشعارات Push من المتصفح.
- **جاهزية التحويل إلى Android وiOS**: بفضل بنية API-first، يمكن بناء تطبيقات أصلية (React Native/Flutter أو Native) تستهلك نفس الـ API دون تعديل الخلفية.

## 16. التوسع متعدد الأبعاد

- **تعدد الفروع**: كل متجر يمكن أن يملك عدة فروع فعلية بمخزون وموظفين وتقارير مستقلة، مع تجميع على مستوى المتجر/المؤسسة.
- **تعدد المتاجر**: مؤسسة واحدة (Owner) يمكنها إدارة أكثر من متجر (علامات تجارية مختلفة) من حساب واحد.
- **تعدد الدول**: كل متجر/فرع يمكن أن يخدم دولًا متعددة بقواعد شحن وضرائب وعملات مختلفة لكل دولة.
- **تعدد العملات**: عرض ومحاسبة بعملات متعددة كما ورد في القسم 8.
- **تعدد المناطق الزمنية**: كل مستخدم/فرع يعرض التوقيت والتقارير بمنطقته الزمنية، مع تخزين موحد بتوقيت UTC في قاعدة البيانات.

## 17. التوثيق ومعايير الجودة

- **توثيق كامل للكود**: تعليقات توثيقية على مستوى الوحدات العامة (Public APIs/Modules) فقط عند وجود منطق غير بديهي، توثيق معماري (ADRs) للقرارات الكبرى، وتوثيق API تلقائي (OpenAPI) يبقى متزامنًا مع الكود.
- **Clean Architecture**: فصل واضح بين طبقات العرض (Presentation)، منطق الأعمال (Domain/Use Cases)، والبنية التحتية (Infrastructure: قاعدة بيانات، تكاملات خارجية)، بحيث تكون طبقة الأعمال مستقلة عن أي إطار عمل أو قاعدة بيانات محددة.
- **مبادئ SOLID** مطبّقة عبر الخدمات والوحدات (كل خدمة بمسؤولية واحدة، الاعتماد على تجريدات (Interfaces) لا تفاصيل تنفيذ).
- **أفضل الممارسات العامة**: اختبارات آلية (Unit/Integration/E2E)، تكامل مستمر (CI) يشغّل الاختبارات والفحص الأمني قبل كل دمج، مراجعة كود إلزامية (Code Review)، وإدارة إصدارات دلالية (Semantic Versioning) لواجهة الـ API.

## 18. خارطة الطريق المقترحة للتنفيذ

هذا القسم اقتراح عملي لتحويل المواصفات أعلاه إلى مراحل تنفيذ قابلة للتسليم بشكل تدريجي:

1. **المرحلة 1 — الأساس**: نموذج البيانات الأساسي، RBAC، لوحات Owner/Admin، إدارة المنتجات/الفئات/الطلبات/العملاء، REST API الأساسي، المصادقة (JWT + 2FA).
2. **المرحلة 2 — التجارة الكاملة**: المخزون متعدد الفروع، الفواتير والضرائب، الشحن والدفع، الكوبونات والعروض، المحافظ ونظام الولاء.
3. **المرحلة 3 — واتساب وCRM**: تكامل WhatsApp Cloud API الكامل (Webhooks، Templates، Catalog)، مركز المحادثات Omnichannel، CRM.
4. **المرحلة 4 — الذكاء والتحليلات**: البحث الذكي، التوصيات، استرجاع السلة المهجورة، البوت الذكي، لوحات التحليلات اللحظية.
5. **المرحلة 5 — التحصين والتوسع**: WAF، مراقبة الأداء والتنبيهات، Queue/Redis/CDN، تجهيز Microservices للخدمات عالية الحمل، PWA، والتحضير لتطبيقات الجوال.
